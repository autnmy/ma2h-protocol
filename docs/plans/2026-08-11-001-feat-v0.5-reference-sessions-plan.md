# feat: v0.5 reference — sessions, addressed routing, bounce + bridge example (#26)

## Summary

Implement the reference half of SCP #24's conformance gate: teach `reference/src/hub.ts` the v0.5
session registry, submit-time destination validation, addressed routing, session-scoped drain,
first-claim-wins claims, bounce-on-terminal with receipts, delivery-track truthfulness, and the §8.8
resolve binding; teach `reference/src/agent.ts` to consume all four entry kinds and run the
bridge-loop worked example with distinct nonzero exit codes; add the three §9.8 signed contexts to
`reference/src/types.ts` + `reference/src/signing.ts`, reproducing the deterministic fixtures in
`examples/entry-signatures-v0.5.md` byte-for-byte.

**Spec of record:** `spec/v0.5.md` (where SCP #24 and spec text differ, the merged spec wins).

## Problem Frame

The v0.5 spec + schemas merged (#25) but the reference implementation still targets v0.4: no
sessions, no `to` routing, no entry kinds beyond directives, no bounce, no resolve binding. The
conformance issue (#27, concurrent) needs hub/agent behavior to prove its downstream vectors
against. Lane rule: this work owns `reference/src/**` and `examples/**` only — `conformance/vectors/**`
and `conformance/README.md` belong to #27.

## Key Technical Decisions

1. **Type names stay stable for downstream vendoring** (`A2hMessage`, `A2hResponse`, `A2hVersion`,
   `InboundDelivery`, …). All v0.5 surface is additive: new types (`Session`, `InterAgentMessage`,
   `ReceiptEntry`, `InboxEntryDelivery` union, three signed-context interfaces) and optional fields
   (`AgentDescriptor.session`, `BaseEnvelope.to`, `SubmitAck.destination`, widened status/state enums).
2. **One generalized mailbox record.** `DirectiveRecord` generalizes to a kind-discriminated
   `EntryRecord` (`directive` | `message` | `response` | `receipt`) carrying addressing metadata
   (`addressedSession?`), claim state (`claimedBySession?`, `streamClaimed?`), and the existing
   visibility/ack/delivered fields. The per-`agent.id` mailbox map stays; filtering happens at drain.
3. **Signing helpers mirror the existing per-context pattern** — `build*SignedContext` +
   `compute*Sha256` + `sign*`/`verify*` delegating to the shared `signCanonical`/`verifyCanonical` —
   one triple per §9.8 context, so #27's vector runner can compose them exactly as dp-001/dp-005 do.
   The `response` entry digest **reuses `computePayloadSha256`** (spec: byte-identical §9.2 code path).
   `resolved_at` in the response-entry context is `string | null` (JSON `null` when a task Response
   has no detail). `receipt_sha256` uses the fixed six-key wrapper with absent-as-`null`.
4. **Sessions are lazily expired against injected `now`.** No timers: every touchpoint
   (register/list/drain/ack/submit/resolve/close) first settles lease lapse for the sessions it
   touches; an explicit `sweepSessions(now?)` exists for tests and models the GC. Terminal transition
   runs exactly once (first-terminal-wins CAS) and fires the §14.2 bounce.
5. **Reachability derives from session-bearing activity only** (§15.1 split): the `destination`
   snapshot and the addressed-path error split use per-session `last_seen` of **live** sessions;
   the v0.4 principal-level presence read stays untouched. A Hub-level
   `sessionVisibility` option (default on, modeling `sessions.agent_list_visibility`) collapses
   terminal→`410` to `422 unknown_destination` and the snapshot to `{state:"unknown"}` when off.
6. **Auth stays in-process.** The `principal` argument remains the authenticated identity (as today,
   documented). The bridge example maps `HubError` codes to exit codes rather than inventing a token
   layer: `unauthenticated`/`not_authorized`/`agent_id_mismatch` → auth exit; drain `gone` (own
   terminal session) → terminal-session exit; §9.8 verification failure → signature exit.
7. **Retention is modeled, not scheduled**: a `retentionDays` Hub option plus an explicit
   `sweepRetention(now?)` applying §14.2: queued-past-retention → `expired` (never delivered);
   principal-addressed delivered-but-unacked past retention → `bounced` `prior:"delivered"` (receipt
   `session` = last claimant); response track short of `delivered-to-agent` at retention → `expired`.
   Both undeliverable terminals auto-resolve addressed ask/task (`cancelled`/`dismissed`,
   `system:undeliverable`) through the same §7 CAS.
8. **Stream is modeled minimally but honestly**: `streamClaim(principal, session, opts?)` models an
   SSE push — starts the visibility window and signs per delivery but does **not** stamp `delivered`
   (server-originated); a later ack (or drain) is the client-originated evidence that advances the
   track. `streamHoldBoundMs(session, now?)` computes the §8.7.2 bound (lesser of advertised hold and
   a nonzero margin before lease expiry) so the zombie-socket rule is executable. Long-poll drain
   stays the conformance floor.
9. **Idempotency replay is out of scope** (pre-existing gap: the reference Hub has never implemented
   §8.1 dedup; the issue scope does not list it). The owning-track GET/status truthfulness — an
   addressed notify's `status` mirroring its mailbox track — IS in scope.
10. **CLI**: `ma2h validate` becomes version-aware (auto-detects `ma2h_version` ≥ 0.5 → v0.5 schema
    registry; `--as` gains `session`/`resolve`/`submit-ack`), clearing the README's v0.4-only note.

## Implementation Units

### U1. types.ts — v0.5 domain types (additive)

**Goal:** every v0.5 shape exists as a typed, schema-mirroring interface; nothing existing renames.
**Files:** `reference/src/types.ts`
**Approach:** add `SessionState`/`Session`/`SessionRegisterRequest`; `AgentDescriptor.session?`;
`BaseEnvelope.to?`; `InterAgentMessage` (delivered form: envelope + `id` + `from` + `to`, no
`state`/`client_ref`); `ReceiptEntry`; `InboxEntryDelivery` union (directive|message|response|receipt
+ signature); `MessageEntrySignedContext`, `ResponseEntrySignedContext` (`resolved_at: string|null`),
`ReceiptSignedContext`; `ResponseDetail.checklist?`; widen `SubmitAck.status` + add
`SubmitAck.destination?`; `MailboxState`/`MailboxTrack` (queued|delivered|acknowledged|bounced|expired);
add `"bounced"` to `DeliveryState`, `"expired"` to `ResponseDeliveryState`; `Capability.sessions?` +
`Capability.inter_agent?`; `GetMessageBody.mailbox?`.
**Test scenarios:** compile-time only (typecheck is the gate); runtime shapes covered by U2–U6 tests.
`Test expectation: none — types-only unit, verified by tsc + downstream units.`

### U2. signing.ts — the three §9.8 contexts

**Goal:** sign/verify all three entry contexts, reproducing `examples/entry-signatures-v0.5.md` exactly.
**Files:** `reference/src/signing.ts`, `reference/test/entry-signing.test.ts` (new)
**Approach:** `computeMessageEntryPayloadSha256` (JCS `{message: <present content fields>}` over
`type,title,body,priority,tags,context,request,action,sensitive`), `buildMessageEntrySignedContext`,
`signMessageEntry`/`verifyMessageEntry`; `buildResponseEntrySignedContext` (digest via existing
`computePayloadSha256`; `resolved_at` null rule), `signResponseEntry`/`verifyResponseEntry`;
`computeReceiptSha256` (six fixed keys, absent→null), `buildReceiptSignedContext`,
`signReceipt`/`verifyReceipt`. All delegate to `signCanonical`/`verifyCanonical`.
**Test scenarios:**
- Each context reproduces the fixture file's canonical JCS bytes, digest, and `v1` under the test key
  (`ma2h-test-secret-key-0123456789ab`) — all three worked examples.
- Message digest: excludes `id`/`from`/`to`/`created_at`/`expires_at`/`agent`/`idempotency_key`;
  includes `sensitive` when present; tampered `request` diverges digest → verify fails.
- Response digest equals `computePayloadSha256` byte-for-byte for the same payload; `resolved_at: null`
  when detail absent; a context rebuilt with the wrong `to` (foreign session) fails verification.
- Receipt: absent-optional serializes as null (guard with a receipt minus one optional); tampered
  `prior` diverges digest; wrong `to` fails.

### U3. hub.ts — session registry (§16)

**Goal:** register/renew/close/expire with first-terminal-wins CAS, kill-switch, visibility, caps.
**Files:** `reference/src/hub.ts`, `reference/test/sessions.test.ts` (new)
**Approach:** `SessionRecord` map + per-agent live index; `registerSession(principal, req?, now?)`
(mints `sess_`, clamps ttl to min/max opts, rejects `#`-bearing principal `invalid_field`, enforces
`maxLivePerAgent` → `rate_limited`); internal `renewSession` on qualifying client-originated activity
(registration, `?session=` drain, `?session=` ack, submit naming `agent.session`, stream claim);
`closeSession(id, caller, now?)` — owner principal or the account's human (kill-switch via
`presenceOwners`); idempotent re-close returns the terminal record; foreign/unknown indistinguishable
(`not_found`); lazy `settleSession(rec, now)` expiry + `sweepSessions(now?)`; terminal transition
(either path) fires `bounceSessionMail` (U5); terminal sessions readable for
`terminalRetentionSeconds` then purged; `listSessions(principal)` own-unconditional;
`getSession(id, caller)` under §16.4 visibility; session reads carry `last_seen`.
**Test scenarios:**
- Register mints `sess_`, state `active`, ttl clamped up to min and down to max; `#`-bearing agent id
  rejected; over-cap → `rate_limited`; sessions of another principal invisible (`not_found` on get,
  absent from list).
- Renewal: a `?session=` drain extends `expires_at` and stamps session `last_seen`; a session-less
  ack renews nothing; lease lapse (injected now) → `expired`, immutable (a later close returns the
  expired record unchanged — CAS).
- Close: owner closes → `closed` + `closed_at`; re-close idempotent; human owner may close (kill-switch);
  non-owner agent and non-owner human → `not_found`; terminal session readable until retention, purged after.

### U4. hub.ts — addressed submit: destination validation + routing + reachability (§4, §8.1)

**Goal:** validate `to`/`agent.session` at accept time; route addressed messages into the destination
mailbox as delivered-form `message` entries; return the truthful ack with the REQUIRED snapshot.
**Files:** `reference/src/hub.ts`, `reference/test/interagent.test.ts` (new)
**Approach:** parse `to` by the first-`#` grammar; sender-side symmetry (submitter id with `#` +
`to`/`agent.session` → `invalid_field`); `agent.session` validation (foreign/unknown → `invalid_field`
422, own-terminal → `destination_gone` 410) + submit renews the named session; destination validation
(known agents = `presenceOwners` provisioning; unknown/cross-account → `unknown_destination`;
session-addressed: unknown session → `unknown_destination`, terminal → `destination_gone`, collapsed
to `unknown_destination` when `sessionVisibility` off); sender allowlist (`setSenderAllowlist`) block
→ `unknown_destination` (indistinguishable); build delivered form (Hub-attested session-qualified
`from`, strip `state`/`client_ref`/callbacks, keep `idempotency_key`), enqueue as `message` entry
(with `addressedSession` when session-addressed), mailbox track `queued`; ack status `queued`
(addressed notify) / `open` (ask/task) + REQUIRED `destination` snapshot from live-session
`last_seen` (`{state:"unknown"}` without `last_seen` when visibility off); addressed notify record
status mirrors its mailbox track thereafter.
**Test scenarios:**
- Grammar: `to: agent:x#sess_ok` parses; unknown agent → 422 `unknown_destination`; unknown session →
  422; own-account terminal session → 410 `destination_gone`; visibility off → both collapse to 422;
  cross-account destination → 422 identical to unknown; allowlist block → 422 `unknown_destination`.
- Sender symmetry: submitter id containing `#` submitting addressed → 422 `invalid_field`; its
  human-inbox submit unaffected. Registration for `#`-bearing id rejected (U3 overlap, asserted here).
- `agent.session`: foreign session → 422; own-terminal → 410; valid session renews lease.
- Ack: addressed notify → `queued` + destination; addressed ask → `open` + destination; destination
  `online` iff a live session of the destination has fresh session-bearing activity; `offline` +
  `last_seen` when stale; `{state:"unknown"}` (no last_seen) when never-seen or visibility off;
  human-inbox submits carry NO destination (misroute detector).
- Delivered form: entry carries Hub-attested `from` (`agent:<id>#<sess>` when submit named a session),
  no `state`/`client_ref`/`request.callback`; validates against the v0.5 inbound-message schema.

### U5. hub.ts — session-scoped drain, claims, per-kind acks, bounce, resolve binding (§8.7.1, §8.8, §14.2)

**Goal:** the mailbox speaks all four kinds with truthful tracks; terminals bounce; addressees resolve.
**Files:** `reference/src/hub.ts`, `reference/test/interagent.test.ts`
**Approach:**
- Drain: session-less → v0.4 shape (principal-addressed directives only — no session-addressed
  entries, no v0.5 kinds); `?session=` → validate (foreign/unknown `not_found` 404, own-terminal
  `gone` 410 — distinct by design), renew lease, return principal-addressed directives +
  session-addressed entries for that session + principal-addressed `message` entries
  (first-claim-wins: the visibility window IS the claim; record `claimedBySession`) + `response`/
  `receipt` entries for that session; FIFO first delivery; per-kind §9.7/§9.8 signature with fresh
  `t`/`jti` each delivery; drain stamps mailbox `delivered` (client-originated).
- Ack: `?session=` presentation validated under drain rules, renews lease only (authorization stays
  credential-scoped); ack keys per kind (directive/message `id`, response `resolution_id`, receipt
  `id`); track effects: message → mailbox `acknowledged`; response → response track `acknowledged`
  (first-ack-wins with `ackMessage`); receipt → consume only; never-presented entries un-ackable
  (stream-claimed counts as presented).
- Bounce on terminal session: every un-acked **session-addressed** directive/`message` entry →
  `bounced` (`prior` = `queued` never drained / `delivered` drained-unacked); receipt entry (Hub-
  originated, `rcpt_`) enqueued to the sender's submitting session iff live; addressed ask →
  `cancelled`, task → `dismissed`, actor `system:undeliverable` via the §7 CAS (no-op if already
  terminal); principal-addressed entries do NOT bounce on a claimant's death (visibility-timeout
  rescue); `response`/`receipt` entries never bounce (dropped silently — pull stays authoritative);
  directive bounces update the directive delivery track (no receipt — human sender has no mailbox).
- `sweepRetention`: KTD 7 rules (queued→`expired`; principal-addressed delivered-unacked→`bounced`
  `prior:"delivered"` with last-claimant session; response track short of `delivered-to-agent` →
  `expired`; undeliverable terminals auto-resolve).
- Resolve binding: `resolveAsAgent(id, principal, body, opts?)` — validate body against
  `resolve-request.schema.json` + verb-match + value-vs-request (`invalid_field`); authz per §9.1
  (addressed default = addressee principal, any session; principal-form entries ignore the actor's
  session qualifier; session-qualified entries match exactly; unaddressed default = submitter;
  account human NOT a default for addressed); `?session=` presentation under drain rules → attested
  session-qualified actor; §7 CAS (late resolve → `already_terminal` 409 with `{id,status,resolution}`;
  expiry-vs-answer precedence); `checklist` carried into the Response detail; on success deliver:
  push callback, pull, and — when the Caller's submitting session is live — a `response` entry
  (dedup-safe: same `resolution_id` on every channel).
- GET: addressed messages carry the `mailbox` object (sender-authoritative; `bounced` +
  `delivered_at` present = seen-then-orphaned); addressed notify `status` mirrors the track.
- Stream: `streamClaim` (claims + signs, no `delivered` stamp) + `streamHoldBoundMs` (lesser of
  advertised hold and lease margin; nonzero margin).
**Test scenarios:**
- Session-less drain sees only v0.4 directives (a queued message entry + session-addressed directive
  + response + receipt all invisible); 0.4 consumer shape unchanged.
- Foreign session drain → 404; own-terminal → 410 (distinct); drained entries verify against their
  §9.8 contexts; redelivery re-signs with fresh `t`/`jti`.
- First-claim-wins: two sessions of one principal drain concurrently → exactly one receives the
  principal-addressed entry within the window; after the window lapses un-acked, the sibling can
  claim; the claimant's ack consumes.
- Per-kind acks: message ack advances sender's `mailbox` to `acknowledged`; response-entry ack
  advances the response track (and a subsequent `ackMessage` is the idempotent no-op — first-ack-wins);
  receipt ack merely consumes; acking a never-presented id is a no-op; `?session=` on ack renews the
  lease but grants nothing.
- Bounce: close a session holding (a) a queued session-addressed ask → `bounced` `prior:"queued"`,
  ask auto-`cancelled` by `system:undeliverable`, receipt delivered to the sender's live session
  (verifies, dedups on `(in_reply_to,event)`); (b) a drained-unacked entry → `prior:"delivered"`;
  (c) a principal-addressed claimed entry → NOT bounced, redelivered to a sibling after the window;
  (d) sender session dead → no receipt, pull still authoritative (`mailbox: bounced`).
- Auto-resolve CAS: addressee resolves before the bounce → bounce is a no-op (existing Response
  stands); addressed notify bounce → no resolution track touched, GET/status reads `bounced`.
- Retention: queued entry past retention → `expired` + ask auto-cancelled; delivered-unacked
  principal-addressed → `bounced` `prior:"delivered"`; resolved-but-never-pulled response track →
  `expired` (never rewrites a `delivered-to-agent`).
- Resolve binding: addressee resolves (bare + session-qualified match rules); submitter's own resolve
  of its addressed ask → `not_authorized`; account human not a default resolver for addressed;
  wrong-verb resolution / `value` on `declined` / missing `value` on `answered` / bad option value →
  `invalid_field`; late resolve → 409 `already_terminal` with real outcome; expiry beats a late
  resolve; `checklist` lands in the Response; live submitting session receives the `response` entry
  (same `resolution_id` as the pull), terminal session falls back with no bounce.
- Stream: `streamClaim` starts the window but leaves `mailbox: queued`; its ack advances
  (delivered evidence at ack time); unacked stream claim reverts to drainable after the window;
  `streamHoldBoundMs` < lease expiry by a nonzero margin and ≤ advertised hold.

### U6. agent.ts — entry consumption + the bridge loop with exit codes (§13.4 + amendments)

**Goal:** a conformant consuming bridge: verify → addressee check (session-qualified) → declared
policy → act → ack → close, exiting loud with distinct codes.
**Files:** `reference/src/agent.ts`, `reference/test/bridge.test.ts` (new)
**Approach:** extend `Agent` with `session?` (current own session, settable on re-register) and
`allowedSenders?` (the deployment-declared policy — explicit, no implicit default);
`receiveEntry(entry, signature, now?)` dispatching by kind: message (shape-validate against the
union schema, verify §9.8, addressee check incl. session qualifier — a prior own session refused,
policy check before acting on ask/task, id dedup + in-flight reservation, sanitize), response
(verify with reconstructed `to`/`id`/null `resolved_at`, dedup `(in_reply_to,resolution_id)`),
receipt (verify digest, dedup `(in_reply_to,event)`); shared jti cache. Bridge:
`runBridgeLoop(hub, opts)` in `agent.ts` — register session → bounded drain loop (`maxIterations`/
deadline, models reconnect-as-renewal) → per-entry verify/act/ack (with `?session=`) → close on
completion; failures throw `BridgeExitError` with pinned distinct nonzero codes
(`EXIT_AUTH_FAILURE=2`, `EXIT_SESSION_TERMINAL=3`, `EXIT_SIGNATURE_FAILURE=4`) — mapped from
`HubError.code` (`unauthenticated`/`not_authorized`/`agent_id_mismatch` → 2; drain/ack `gone` → 3)
and from §9.8 verification failure (→ 4); never a silent swallow. `demo/playground.ts` untouched;
a small `bin`-reachable demo is optional and only if trivially additive.
**Test scenarios:**
- Happy path: bridge registers, drains a session-addressed ask, verifies, policy permits the sender,
  resolves via `resolveAsAgent`, acks with `?session=`, closes; hub shows `acknowledged` mailbox +
  `answered` resolution; sender's live session got the `response` entry.
- Addressee check: entry session-qualified to the bridge's *prior* session → refused (not acted on);
  principal `to` of another agent → refused.
- Policy: ask from a principal outside `allowedSenders` → not acted on (still verifiable);
  policy unset → ask/task refused (explicit-config MUST); notify exempt from the act gate.
- Exit codes: transport throwing `unauthenticated` → exits code 2; draining with an expired own
  session → code 3 (distinct from 2); a tampered entry signature → code 4; each surfaced as
  `BridgeExitError`, none swallowed.
- Response/receipt entries: response entry dedups against the same `resolution_id` arriving by pull;
  receipt entry dedups on `(in_reply_to,event)`; tampered receipt rejected.
